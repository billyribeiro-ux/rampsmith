# ADR-201: A synthetic theme corpus, its golden file format and its span format

- Status: Accepted
- Date: 2026-10-18
- Stream: WS-11 (`corpus/`, `packages/corpus-tools/`)

## Context

PLAN §23 asks for a theme test corpus: "Shopify's open-source reference themes, included only
after their licenses are checked, plus synthetic themes that reproduce known failure patterns",
each carrying "golden findings: the expected rule ids and source spans after mapping", with a
mapping-accuracy target. R2 (PLAN §5) measures the patch engine on the same corpus: "fixes at
least 90% of targeted findings on the theme test corpus with zero render regressions".

The architect ruled on 17 Oct 2026 that Dawn files stay out of this repository: Dawn's licence
allows use "only ... to develop themes that integrate or interoperate with Shopify" and the
question is on the attorney's list (STATUS.md, "Architect rulings"; LAUNCH.md C row 13). Every
theme here is therefore synthetic.

Shopify theme architecture, read on shopify.dev on 2026-10-17:

- [Theme architecture](https://shopify.dev/docs/storefronts/themes/architecture): "Only a
  `layout` directory containing a `theme.liquid` file is required"; the directories are
  `assets`, `blocks`, `config`, `layout`, `locales`, `sections`, `snippets`, `templates` (with
  `templates/customers` and `templates/metaobject`), and "Subdirectories, other than the ones
  listed, aren't supported". Theme JSON may carry comments and trailing commas, but files users
  do not edit by hand (`templates/*.json`, section groups, `config/settings_data.json`,
  `locales/*.json`) do not keep them.
- [JSON templates](https://shopify.dev/docs/storefronts/themes/architecture/templates/json-templates):
  required `sections` and `order`; optional `layout` (`false` renders without one) and `wrapper`
  (`div`, `main` or `section`, written like `div#div_id.div_class[attribute-one=value]`);
  sections render in `order` "with no markup between the sections"; up to 25 sections and 50
  blocks per section.
- [Section schema](https://shopify.dev/docs/storefronts/themes/architecture/sections/section-schema):
  a section "is wrapped in a `<div>` element with a unique `id` attribute",
  `<div id="shopify-section-[id]" class="shopify-section">`; `tag` may be `article`, `aside`,
  `div`, `footer`, `header` or `section`; `class` adds to `shopify-section`.
- [The `section` object](https://shopify.dev/docs/api/liquid/objects/section): JSON-template
  section ids "are dynamically generated by Shopify" (example `template--14453298921537__cart-items`);
  a static section's id is its file name.
- [Section groups](https://shopify.dev/docs/storefronts/themes/architecture/section-groups):
  `type`, `name`, `sections`, `order`, rendered with `{% sections 'header-group' %}`. The page
  does not give the id format of a group's sections.
- [Theme blocks](https://shopify.dev/docs/storefronts/themes/architecture/blocks/theme-blocks)
  and [`content_for`](https://shopify.dev/docs/api/liquid/tags/content_for): blocks live in
  `blocks/`, sections opt in with `@theme`, `{% content_for "blocks" %}` renders them in the
  stored order, `{% content_for "block", type:, id: %}` renders a static one. Neither page
  describes a wrapper element around a block.
- [Layouts](https://shopify.dev/docs/storefronts/themes/architecture/layouts):
  `content_for_header` inside `<head>`, `content_for_layout` inside `<body>`; other layouts are
  chosen by a JSON template's `layout`.
- [settings_data.json](https://shopify.dev/docs/storefronts/themes/architecture/config/settings-data-json)
  and [input settings](https://shopify.dev/docs/storefronts/themes/architecture/settings/input-settings):
  `current` holds the saved values keyed by setting id (example `"color_page_bg": "#FFFFFF"`);
  the storage format of `color_scheme_group` is not documented on these pages.

## Decision

1. **Synthetic themes only**, written by hand for Rampsmith, copying no third-party theme code:
   three failing themes in three markup traditions (aurora: current conventions; birch: older
   themes still live; cedar: theme blocks and custom widgets) and a **control twin** of each with
   every golden finding fixed. Colours use plain `color` settings, whose storage is documented,
   not colour scheme groups, whose storage is not.
2. **Fixture stores.** Themes render a fixture store (`fixtures/store.json`, "Harbor & Pine") with
   products, media, collections, pages, an article, menus, a cart and search results. Its data-audit
   failures (media alt text, rich text) belong to the store, not to a theme, so they live in
   `golden/store-harbor.json`; controls render `fixtures/store-clean.json`, the same store with
   those failures fixed.
3. **Golden file format** (`schema/golden.schema.json`, JSON Schema 2020-12). Per finding: a
   stable id; the rule id and its engine (`axe`, `rampsmith-browser`, `rampsmith-data`); the outcome
   (`violation` or `incomplete`, axe-core's and a11y-rules' terms); impact; the rule's WCAG 2.2
   criteria; the PLAN §12 fix-catalog category; occurrences (page and selector, `*` for every
   page); the expected mapping (`deterministic`, `ambiguous` with the reason, or `none` for
   data-audit findings); the span; optionally `rendersFrom`, the element that renders the node
   when the span points elsewhere (a colour setting); and the expected fix (channel, recipe,
   outcome `fixed`, `refused` with liquid-patch's refusal code, or `review`, recipe parameters,
   and `targeted`).
4. **Span format**, aligned with `packages/liquid-patch` at `551b200`: offsets are UTF-16 code
   units into the file decoded from UTF-8 (ADR-101); an element span's `start` is the offset of
   the `<` of its start tag (`RecipeTarget`, ADR-102) and adds the tag name. Three more kinds cover
   targets that are not elements: a JSON value by RFC 6901 pointer (PLAN §12 step 5 maps
   setting-driven colours to `config/settings_data.json`), a CSS declaration inside a named rule,
   and store data in a11y-rules' `DataLocation` shape (resource GID, field, offsets). Every span
   carries an `anchor`, the source text at its start, so files stay reviewable and offsets can be
   re-found after an edit.
5. **Section ids.** Template sections get `template--<n>__<key>`, Shopify's documented form, with
   `n` a deterministic FNV-1a hash of theme and template. Group sections get
   `sections--<n>__<key>`, a corpus convention because the format is undocumented; a mapper must
   resolve a wrapper through the `__<key>` suffix and the group's JSON, not through the prefix.
6. **Variety on purpose**: CRLF snippets (kept by `corpus/.gitattributes`), tabs, unquoted and
   single-quoted attributes, `{% include %}`, `img_url`, `data-src`, `.css.liquid`, `{% liquid %}`,
   `inline_asset_content`, `{% stylesheet %}`, template suffixes, static sections and theme blocks.

## Consequences

- No licence question attaches to the corpus; it can grow with any failure pattern found in the
  field, written fresh.
- The golden files are the single source of expected results: the browser check proves they are
  complete and exact for axe-core, and the runner scores mapper and engine against them.
- Control twins show that each expected fix, written the way the recipes write it, renders clean.

## Plan correction

PLAN §23, "Theme test corpus (`corpus/`)", first two bullets. Replace:

```markdown
- Shopify's open-source reference themes, included only after their licenses are checked, plus synthetic themes that reproduce known failure patterns.
- Each theme carries golden findings: the expected rule ids and source spans after mapping.
```

with:

```markdown
- Synthetic themes written for Rampsmith that reproduce known failure patterns in the markup styles real themes use, each with a control twin that has every finding fixed; no Shopify reference theme files (Dawn's licence limits their use, architect ruling of 17 Oct 2026; ADR-201).
- Each theme carries golden findings: the expected rule ids, source spans after mapping, WCAG 2.2 criteria and expected fix outcome (format and runner contract: corpus/CONTRACT.md).
- Patch engine target: at least 90% of targeted findings fixed with zero render regressions (R2), computed as corpus/CONTRACT.md defines.
```

## Rejected alternatives

- Vendoring Dawn or another reference theme: ruled out by the architect pending the attorney.
- Generating themes from templates: real themes vary in ways a generator smooths away; hand
  writing keeps the oddities the mapper must survive.
- Byte offsets: the parser and liquid-patch use UTF-16 code units (ADR-101).
- Golden selectors in axe-core's own target syntax: axe chooses selectors heuristically and
  they change with the DOM; the check compares elements, so golden selectors can be written to
  survive the expected fix.
