# ADR-023: Web skeleton, the embedded App Home and its security headers

- Status: Accepted
- Date: 2026-10-17

## Context

R0 step 8 needs the SvelteKit app with the embedded App Home (App Bridge and Polaris) and the
standalone shell. Versions were read from npm on 2026-10-17: `@sveltejs/kit` 3.1.0 (peers:
`vite ^8.0.12`, `svelte ^5.57.1`, `typescript ^6.0.0`, `@opentelemetry/api ^1.0.0`), `svelte`
5.57.2, `vite` 8.3.4, `@sveltejs/vite-plugin-svelte` 7.3.1, `@sveltejs/adapter-node` 6.0.0,
`svelte-check` 4.7.7, `eslint-plugin-svelte` 3.23.1, `prettier-plugin-svelte` 4.1.1,
`@inlang/paraglide-js` 2.29.0, `@playwright/test` 1.64.1, `@axe-core/playwright` 4.14.0.
SvelteKit 3 moved configuration into the Vite plugin, replaced `$lib` with a `#lib` subpath
import, replaced `$env/*` with `src/env.ts` and `$app/env/*`, and made server tracing a
top-level `tracing.server` option loaded with `src/instrumentation.server.ts`.

Shopify's documentation (read 2026-10-17) says: App Bridge is included with
`<meta name="shopify-api-key">` and `https://cdn.shopify.com/shopifycloud/app-bridge.js`, and
App Review requires "the latest App Bridge script"; Polaris web components are published with
semantic versioning (`polaris-1.js` major channel, `polaris-1.1.js` exact, stable since
22 September 2026); `frame-ancestors` must name `https://admin.shopify.com` and the one shop,
never a wildcard ("Set up iframe protection", the `STATIC_FRAME_ANCESTORS` check).

## Decision

1. `apps/web` is SvelteKit 3.1 with `adapter-node`, runes only, `#lib/*` imports, config in
   `vite.config.ts`, environment variables declared and validated in `src/env.ts`
   (`API_URL` private, `SHOPIFY_CLIENT_ID` public; both required at runtime, optional at build).
2. **App Bridge is the one evergreen script.** Shopify publishes it only unversioned and
   requires the latest; this is the documented exception to "no floating CDN tags" (CLAUDE.md),
   and the documentation wins. **Polaris is pinned** to `polaris-1.1.js`; moving to a new
   release is a reviewed change.
3. **The embedded shell carries no data** (S-4, ADR-022). It renders on the server, then the
   page asks `/app/api/session` with a token from `shopify.idToken()`; a 401 with
   `X-Shopify-Retry-Invalid-Session-Request: 1` is retried once with a new token. PLAN §16's
   "works before JavaScript loads" holds for the marketing site and the standalone dashboard;
   the embedded admin cannot work without App Bridge, which is JavaScript.
4. **Headers.** SvelteKit's `csp` option sets `script-src 'self' https://cdn.shopify.com` with
   per-request nonces, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`. The
   `handle` hook appends `frame-ancestors https://admin.shopify.com https://<shop>` on `/app`
   routes when the launch URL's `shop` parameter is a valid `*.myshopify.com` host, and
   `frame-ancestors 'none'` everywhere else; plus `nosniff`, a strict referrer policy, a
   permissions policy, and HSTS over HTTPS. The unverified `shop` parameter only widens framing
   to that shop; it grants no data.
5. **Messages** live in `messages/en.json`, compiled by Paraglide. The inlang message-format
   plugin is installed from npm (4.5.4) and loaded from `node_modules`, not from a CDN URL, so
   compilation is offline and pinned. The compiled output is git-ignored and regenerated by
   `pnpm run i18n` before type checks, tests and builds.
6. **Tracing.** `tracing.server` is on; `instrumentation.server.ts` starts
   `@rampsmith/telemetry` (exports only when `OTEL_EXPORTER_OTLP_ENDPOINT` is set). Calls to the
   api inject W3C `traceparent`, so api spans join the request's trace.
7. **Tests.** Vitest for pure modules (`frameAncestors`, `sessionFetch`, the session forwarder,
   trace propagation). Playwright drives the built app in Chromium with a stub App Bridge and a
   stub api, runs axe with the WCAG 2.0–2.2 A/AA tags on every page state, and checks the
   keyboard path of the skip link. The `e2e` CI job installs Playwright's pinned Chromium; the
   sandbox points `PLAYWRIGHT_CHROMIUM_EXECUTABLE` at its local Chromium (ADR-014).

## Consequences

- The CSP has not yet been exercised inside Shopify admin; the dev-store runbook includes
  checking the browser console for CSP reports on first load.
- `ORIGIN` no longer exists in `adapter-node` 6; the deployed origin is set through
  `paths.origin` when the Railway domain is known.

## Rejected alternatives

- Server-side rendering of shop data from an `id_token` search parameter: undocumented (S-4).
- `frame-ancestors https://*.myshopify.com`: flagged by Shopify as permissive.
- Polaris through the floating `polaris.js`: changes under us without review.
